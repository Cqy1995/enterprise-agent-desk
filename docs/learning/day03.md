## 本地工具实践

```bash
npm run learn:tool -- T1001
npm run learn:tool -- T9999
npm run learn:tool -- T2001
```

工具定义与程序实现在ticket-tool.mjs，运行入口在06-query-ticket.mjs。第一条查询当前用户的模拟工单，预期found；第二条不存在，预期not_found；第三条属于其他用户，也返回not_found，不暴露该记录是否存在。

三层边界：参数结构/类型/编号规则由程序校验；操作权限由服务端上下文决定；查询范围限制为当前用户数据。若无查询权限返回forbidden。context身份不是模型参数，示例用户只是本地常量，尚未实现登录认证。

输入不合规时抛错，不通过重试修正类型；not_found是正常业务结果，不是系统故障。后续接入模型时再添加调用ID与工具结果消息。

## 模型调用工具入口

```bash
npm run learn:tool:live -- "帮我查一下T1001现在处理到哪了"
```

最多2次真实模型请求，非流式、每次最多512输出Token，不自动重试。第一轮向模型提供工具定义，模型选择直接回答或请求getTicket；请求工具时，程序解析参数，使用本地可信上下文执行查询，再追加assistant工具调用消息和带tool_call_id的tool结果；第二轮用tool_choice=none让模型基于结果总结。

调用ID负责配对消息，context负责身份权限，两者都不是operationId。查询结果仍应核对最终回答是否忠于事实。缺少编号时预期直接追问，只产生一次模型请求；未找到不应被模型编造成处理进度。

本课只处理一张工单、一个工具调用，不支持无限循环；多工具和执行步数控制在D04展开。协议核对来源：https://api-docs.deepseek.com/guides/tool_calls/ 。

AI模拟验证：查到、未找到、其他用户记录不可见、缺少编号不执行工具、参数类型错误、无效参数JSON、模型注入额外身份参数、未知工具拒绝执行；验证第二轮消息中assistant工具请求和tool结果按调用ID匹配，并验证原分类调用仍可用。模拟最终回答不证明真实模型一定忠于工具事实。

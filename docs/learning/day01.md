## 解释检查

1. API Key在哪里读取？为何只存在服务端本地配置？
2. messages里哪些信息定义规则，哪些展示例子，哪些是本次输入？
3. 为什么JSON.stringify请求体？Content-Type和Authorization分别做什么？
4. HTTP 401、429和网络连接失败有什么不同？
5. 从哪个字段读最终答案？usage实际返回哪些字段？没有返回的字段如何记录？
6. 如果再问“还是连不上”，应用需要补充哪些上下文？

复习卡：

1. 当前程序是一次LLM分类调用：步骤由程序规定，输出澄清文本后结束；没有模型驱动的工具执行循环。
2. 请求中的所有消息角色均可能贡献输入Token；本次新生成的内容计入输出。max_tokens限制输出上限，不要求填满。
3. 多轮对话由应用提供相关历史、摘要或状态；不能默认一次独立请求自动拥有之前的上下文。
4. Prompt改动用固定标注样例比较，覆盖新问法、模糊输入和正常输入；记录分类、格式与澄清行为，不以单条成功证明提升。
